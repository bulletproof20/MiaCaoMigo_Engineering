# Naming Philosophy

## Purpose

This document defines the naming philosophy adopted for the MiaCaoMigo database system.

The purpose of this convention is to ensure:
- semantic consistency;
- SQL readability;
- maintainability of database logic;
- rapid identification of entities and attributes;
- reduced ambiguity across relational operations.

These conventions are mandatory for all database modules and contributors.

---

# Core Philosophy

The adopted naming convention follows a compact semantic strategy designed to optimize:
- SQL readability;
- procedural programming;
- relational consistency;
- maintainability across all modules.

The convention prioritizes:
- semantic precision;
- compact identification;
- structural consistency across the entire database system.

---

# Language Standards

All database components must use:
- technical English;
- lowercase only;
- snake_case notation;
- standardized semantic abbreviations;
- ASCII-compatible characters only.

---

# Naming Structure

Database attributes must follow the structure:

```text
<prefix>_<entity_suffix>
```

This structure ensures:
- semantic identification;
- reduced ambiguity in relational operations;
- structural standardization across all modules;
- consistent naming readability.

---

# Semantic Consistency

All database modules must:
- preserve the same naming philosophy;
- preserve semantic consistency;
- preserve English technical terminology;
- preserve compact semantic identification;
- preserve structural naming uniformity.

Any new naming pattern introduced into the system must first be standardized and documented before adoption.

---

# Forbidden Naming Practices

The following practices are not allowed:
- mixed casing;
- Portuguese naming;
- spaces in identifiers;
- undocumented abbreviations;
- inconsistent semantic structures;
- generic non-semantic identifiers.

---

# Naming Exceptions

## Contextual Expansion Rules

In specific scenarios where semantic ambiguity or contextual redundancy may occur, additional contextual identifiers may be appended to preserve naming clarity and structural distinction.

This contextual expansion must:
- remain semantically consistent;
- preserve the compact naming philosophy;
- avoid unnecessary verbosity;
- remain structurally standardized.

---

# Dictionary Standardization

All database abbreviations, semantic identifiers and naming structures must be formally documented within the system dictionary.

The dictionary is responsible for defining:
- semantic meanings;
- approved abbreviations;
- contextual identifiers;
- structural naming references.

The naming convention defines the structural philosophy.  
The dictionary defines the semantic interpretation.

---

# Final Notes

The adopted naming convention intentionally prioritizes:
- semantic compactness;
- SQL efficiency;
- procedural readability;
- relational consistency;
- long-term maintainability;
- architectural uniformity.

Consistency across the entire database system takes priority over individual stylistic preferences.
